# Plugin bundle standards

**Derived, never authoritative.** The `deepseek-harness` checkout and the live harness decide behavior and rules; this file is a digest with out-of-tree adaptations, and where it disagrees with them, they win and this file is corrected. A plugin repository's own `STANDARDS.md` or `SCOPE.md` never overrides either.

Rules every out-of-tree bundle in a `dsh-works` repository must satisfy. **MUST** = a reviewer rejects the change; **SHOULD** = omit only with a stated reason in the plugin README. Each rule cites the deepseek-harness source it derives from; paths resolve against that checkout. APIs here are a developer preview and move between releases, so treat a citation as the rule's origin, not as a promise that the installed harness still behaves that way — re-verify against the installed version when a rule decides code.

Mechanics for each surface (code shapes, slot ids, install commands) live in `references/surfaces.md` and `references/build.md`; this file states only the rules the code must satisfy.

## A. Lifecycle and effects

- **A1 (MUST)** Every listener, tool, slot contribution, timer, watcher, and subscription is registered inside `apply` through `ctx.on`, `ctx.effect`, `ctx.tools.register`, or a slot registration, so unload removes it; a module-level or fire-and-forget registration leaks past unload and into the next plugin generation. `docs/user/develop/framework/index.md`
- **A2 (MUST)** Put order-dependent cleanup in one `ctx.effect` that awaits its steps serially; sibling async disposers start concurrently with no serial completion guarantee, so "reverse registration order" is not a teardown plan. `docs/user/develop/framework/index.md#automatic-cleanup`
- **A3 (MUST)** Disposal reaches quiescence, not merely a request for it: await child exit after abort or kill, and keep resources and completion listeners usable until accepted consumers finish. `docs/defensive-patterns/general.md#dispose-must-reach-quiescence-not-just-request-it`; `.agents/skills/cordis-styling-nitpicking/SKILL.md`
- **A4 (MUST)** None of the three P0 lifecycle findings applies: no process-wide singleton, no unreversed side effect left live after unload, and no cleanup dependency released before its consumers settle. A P0 finding is a blocker, not a style note. `.agents/skills/cordis-styling-nitpicking/SKILL.md`
- **A5 (MUST)** The Host entry is exactly one form: a function plugin exporting lower-case `name`/`inject`/`apply` plus optional `Config` and **no default export**, or a service class as the **default** export; mixing them makes the Loader discard the function plugin's namespace. `packages/AGENTS.md`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md`
- **A6 (MUST)** Optional services are read with `ctx.get(name)` at the use site; `ctx.<name>` is reserved for services named in `inject`. The property proxy is topology-sensitive and throws or reads wrong after provider replacement. `docs/user/develop/framework/service.md`; `packages/AGENTS.md`
- **A7 (MUST)** Package modules never `await` at module scope (no `await`, `for await`, `await using`); a module-scope wait stalls every importer and turns a rejection into a module-evaluation failure. `docs/defensive-patterns/package-surface.md#package-modules-do-not-await-at-module-scope`
- **A8 (MUST)** A waterfall listener that does not own the decision returns `next()`; returning nothing short-circuits every later listener, and a rewritten decision is spread (`{ ...decision, messages }`) so envelope fields survive. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md`; `docs/architecture.md#turn-flow`
- **A9 (SHOULD)** Assume the plugin is disposed and re-applied on every config edit, and that replacing an installed package needs a profile restart for a fresh module generation; report `restart-required` instead of promising the change is live. `docs/user/develop/basic/config.md#work-with-hmr`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md`

## B. Module state and shared state

- **B1 (MUST)** Shared mutable state hangs on a service or instance with a lifecycle; a module-level cache, static field, global `WeakMap`, `Symbol.for`, `globalThis`, or `window.__X__` hides the owner and outlives teardown. `docs/defensive-patterns/general.md#shared-state-has-one-owner`; `packages/AGENTS.md`
- **B2 (MUST)** Introduce no global `current`, `active`, or `selection` singleton; a piece of data has several views, each holding its own reference or key, and context comes from the current scope. `docs/defensive-patterns/general.md#a-new-activecurrent-singleton-is-refused`
- **B3 (MUST)** Keep no authoritative state in module memory: a config edit unloads the old instance and loads a new one, so module state either resets silently or leaks across instances. `docs/user/develop/basic/config.md#work-with-hmr`
- **B4 (MUST)** Configuration and credentials that must survive a reload go to `Config` (user-editable in `cordis.patch.yml`) or to `ctx.credentials.modifyRecord()`; never to plugin memory and never to a copied secret in config. `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#persist-your-own-configuration`

## C. Config and tunables

- **C1 (MUST)** Any value two deployments may want differently is a `Config` field; a constant, `DEFAULT_*`, or test hook is not configurability. The test is whether `cordis.patch.yml` changes it without a code edit. `docs/user/develop/basic/config.md#do-not-hardcode-tunable-values`; `AGENTS.md#conventions`
- **C2 (MUST)** Export a Schemastery `Config` schema (a plain object literal does not implement the Standard Schema interface Cordis requires) and let it validate the row's `config` at activation; in plain JS this is the object `Schema.object({...})` returns, exported as `Config`. `docs/user/develop/basic/config.md`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md`
- **C3 (MUST)** Invalid configuration fails the load loudly with an actionable error (FAILED fiber), and self-contained constraints live in the schema rather than in runtime checks after `apply` starts. `docs/user/develop/basic/config.md#fail-loudly-on-invalid-configuration`
- **C4 (MUST)** A patch override replaces the whole `config` value, not a deep merge: restate every key the row needs, not just the changed one. `docs/user/develop/basic/publish.md#the-loading-order`; `docs/cordis-primer.md#loader-configuration`
- **C5 (MUST)** Never read, filter, or rewrite the profile's `cordis.patch.yml`, and never locate it by walking up from the package directory; persist your own settings through `ctx.get('configEditor').edit(entry, ...)` and report a rejection instead of claiming the value saved. `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#persist-your-own-configuration`
- **C6 (MUST)** Only plugin `config` and entry `disabled` accept `!!js` (never `!js`); other entry metadata stays literal, so conditional composition belongs in overlays. `AGENTS.md#secrets--env`; `docs/cordis-primer.md#loader-configuration`

## D. Session and model-visible data

- **D1 (MUST)** The session log is the only source of truth: anything the model sees must be reconstructable from committed session events, and plugin memory is a derived cache. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#principles`; `docs/architecture.md#session-log`
- **D2 (MUST)** Never append a session event with a new `type`: live `Session.append()` cannot set the `ignorable: true` marker that makes unknown stored events readable, so the Session refuses to reopen; `appendPluginRecord()` is reserved for DSH's experimental packages. Derive state from existing events or keep it in a storage service. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#stability`
- **D3 (MUST)** Do not subscribe to `session/event` and rescan the log per view; derive once on the Host from committed events and hand the value to the slot, or use a `ctx.sessionProjections` unit when inspection confirms the registry is present. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#performance`; `references/surfaces.md#session-derived-state`
- **D4 (MUST, if a projection unit is used)** `apply(state, event)` is pure and synchronous, state stays plain JSON, an ignored event returns the same reference, and `stateVersion` is bumped when fields or fold semantics change. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#performance`; `packages/session/session-projection/README.md`
- **D5 (MUST)** Wait on durable events (`turn/end`, `assistant/message`, `tool/result`) for settled facts and render live tokens from `agent/assistant-stream`; never poll `agent/status`, and never treat `whenIdle()` as one follow-up's result because several inputs share one running interval. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#performance`; `docs/defensive-patterns/general.md#async-state-is-not-synchronous-state`
- **D6 (MUST)** `agent.followup()` wakes the agent; `agent.inject()` is logged at call time and does not wake anything. A timer that must cause work calls `followup()`, and its cleanup stays in the owning effect. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#performance`; `docs/cookbook/adding-a-tool.md#rules-of-the-execute-contract`
- **D7 (MUST)** UI-only formatting never enters the canonical value or model content, and stable model-visible text is pinned verbatim in a test rather than left to drift. `docs/cookbook/adding-a-tool.md`; `packages/AGENTS.md`
- **D8 (SHOULD)** Write data that other plugins and older readers can meet: unknown event types, envelope fields, and versions are a compatibility surface, not an internal detail. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#principles`

## E. Errors and user-facing copy

- **E1 (MUST)** Expected failures carry declared types, stable discriminants, and handling-relevant details; preserve causes, keep machine identity separate from display text, and never route handling by parsing messages. `.agents/skills/dsh-error-handling/SKILL.md`
- **E2 (MUST)** Only the affected state's owner may establish safe continuation; otherwise stop dependent work, discard invalid state, or escalate. Logging alone is not recovery, and a retry needs safe repetition, cancellation, and an owner. `.agents/skills/dsh-error-handling/SKILL.md`
- **E3 (MUST)** Every final report states a readable summary, the affected operation, and a safe next action, localized through the host's locale; sensitive internals stay out of user-facing text. `.agents/skills/dsh-error-handling/SKILL.md`
- **E4 (MUST)** An empty `catch` names the error and why, and keeps its `try` to one statement. `AGENTS.md#conventions`
- **E5 (MUST)** Ship `locale/en.json` and `locale/zh.json` with non-empty `meta.title` / `meta.description`; English copy, including those two fields, is sentence case. Missing fields fall back to `package.json` `name`/`description`, which is a visible defect for a delivered plugin. `packages/preset/agent-preset/skills/cordis-plugin-development/SKILL.md`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#display-metadata-and-icon`; `.agents/skills/dsh-prose-standard/SKILL.md`
- **E6 (MUST)** Client UI text goes through the Client locale service — `ctx.locale.register(namespace, { en, zh, ... })` in an effect and `ctx.locale.bind(namespace)` or the framework `t` seat at the render site — never hardcoded in JSX or props. `packages/preset/agent-preset/skills/cordis-plugin-development/references/ui-plugin.md`; `packages/client/locale/README.md`
- **E7 (MUST)** User, model, wire, and code data stays verbatim: ids, paths, URLs, commands, tool names, and JSON literals are never translated, and internal matching uses discriminants or stable ids rather than localized text. `packages/client/locale/README.md`; `.agents/notes/implemented/architecture/2026-08-23-locale-owned-client-ui-copy.md`
- **E8 (SHOULD)** Model-facing tool text describes behavior, puts parameter rules on that parameter, says each fact once, and is re-measured for prompt tokens when it changes. `packages/preset/agent-preset/skills/agent-experience/SKILL.md`

## F. Tool contract

- **F1 (MUST)** Register through `ctx.tools.register(definition)` inside `apply`; `execute` returns exactly one canonical JSON value matching `output.schema`, and human explanation belongs in `output.render`. Never return content blocks from the body or make callers parse prose for ids. `references/surfaces.md#host-tool`; `docs/cookbook/adding-a-tool.md#rules-of-the-execute-contract`
- **F2 (MUST)** The registry validates model arguments against `parameters` before `execute`; hand-check only constraints the DSL cannot express (non-empty, positive, cross-field), and a raw JSON-Schema tool owns its own input validation. `docs/cookbook/adding-a-tool.md`
- **F3 (MUST)** Honor `exec.signal` and cancel in-flight work when it fires; only an around-dispatch wrapper may replace and restore the signal, and it may never remove it. `docs/cookbook/adding-a-tool.md`
- **F4 (MUST)** A throw or an invalid return value means `isError`; a successful domain outcome stays representable in the canonical value even when the renderer explains a non-ideal state. `docs/cookbook/adding-a-tool.md`
- **F5 (MUST)** The UI card is a separate concern: `presentationMeta` derives replayable JSON from the same canonical value, and `presentCall`/`presentResult` are pure functions of args plus result — no I/O, session state, clock, or randomness. `docs/cookbook/adding-a-tool.md#how-your-tool-renders-in-a-ui`
- **F6 (MUST)** The Web Client does not consume `presentCall`/`presentResult`; a specialized card requires a Client registration in the `tool.call.toolview` keyed slot that validates raw wire values itself and returns the generic row for malformed or unsupported input. `docs/cookbook/adding-a-tool.md#web-client-presentation`
- **F7 (MUST)** Long work goes through `ctx.jobs.start({ kind, label, owner: exec.agent, run })`, gated by `Config`, with task-owned cancellation rather than `exec.signal`, and returns a typed canonical handle such as `{ kind: 'background', jobId }`. `docs/cookbook/adding-a-tool.md#long-running-work`
- **F8 (SHOULD)** Do not build deployment policy into the tool; use `tools/pre-execute` for allow/deny/ask, `ctx.tools.guard()` for a monotonic final denial, `tools/execute` to wrap dispatch, `tools/post-execute` to transform, and `tools/result` to observe. `docs/cookbook/adding-a-tool.md#execution-policy-and-observation`

## G. Web UI

- **G1 (MUST)** The client half declares `dsh.client` with `platform: 'web'` plus an `exports["./client"]` bundle whose lazy factory id equals the package name; the factory body carries no side effects, because it runs at materialization, not load. `packages/preset/agent-preset/skills/cordis-plugin-development/references/ui-plugin.md`; `packages/client/modules/README.md#lazy-cjs-model`
- **G2 (MUST)** Contribute through `ctx.slots.inject(ownerKey, () => ctx.slots.register(...))`; a bare `register` into an undeclared slot fails at load, and the contribution must leave with the owning declaration and the plugin fiber. `packages/preset/agent-preset/skills/cordis-plugin-development/references/ui-plugin.md`; `docs/subsystems/slots.md#declaration-and-lifecycle`
- **G3 (MUST)** Never runtime-import, `require`, or load a Harness Client package (for example `@deepseek-ai/dsh-client-ui-primitives`); `dsh.client.inject` is an ordering-only name list and stays allowed. Write your own controls, copy host markup/CSS/behavior, and rename copied classes under your plugin's prefix. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#ui`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/verification.md`
- **G4 (MUST)** Style only with semantic theme tokens (`--dsw-alias-*`); literal colors are for artwork only, and a renamed token must degrade appearance rather than break rendering. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#ui`; `docs/web-styling.md`
- **G5 (MUST)** No iframe of a Host-served page, no append or write to `document.body`, no replacing the app root, no DOM writes outside your component, and no reading another plugin's DOM, stylesheet, or component source to guess placement. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#ui`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/ui-plugin.md`
- **G6 (MUST)** Register styles, timers, and listeners inside `apply` with `ctx.effect`/`ctx.on` and return cleanup; component-local styles may render as React elements so unmount removes them. `packages/preset/agent-preset/skills/cordis-plugin-development/references/ui-plugin.md`
- **G7 (MUST)** A throwing component blanks its slot entry (`slot entry crashed`), so components must be total over their props and fall back to the generic presentation for malformed or unknown data. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#ui`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/verification.md`
- **G8 (SHOULD)** Choose a slot that already allocates the space you need and confirm its options/props from live inspection, rather than planning motion around host controls; set `immediately: true` only for stage-one infrastructure rows. `packages/preset/agent-preset/skills/cordis-plugin-development/references/ui-plugin.md`; `packages/client/AGENTS.md#new-plugin-package-checklist`

## H. Packaging and compatibility

- **H1 (MUST)** `package.json` declares `type: "module"`, `main`, `exports` (`.`, `./client` when a UI half exists, `./locale/*.json`, `./icon`, `./cordis.patch.yml`), and a `files` list covering every runtime file and asset. A linked directory install ignores `files`, so a packed/published bundle must be checked against the real file list. `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#manifest`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#manifest`; `packages/client/AGENTS.md#export-discipline-client-plugin-packages`
- **H2 (MUST)** `dsh.bundle.patch` names one patch file or an ordered list, each path relative to the package root; patch rows mount the package by its bare name. A package without `dsh.bundle` installs as a plain dependency and activates no layer, with a warning. `docs/user/develop/basic/publish.md#the-bundle-manifest`; `packages/util/package-manifest/README.md`
- **H3 (MUST)** `dsh.client` requires the `./client` export (the scan throws without it); `inject` is informational ordering metadata only, and `external` names exact non-baseline infrastructure specifiers — never a way to reach another feature plugin. `packages/client/AGENTS.md#new-plugin-package-checklist`; `packages/client/modules/README.md`
- **H4 (MUST)** Declare `engines.dsh` as a SemVer range covering every supported DSH release; installation and profile startup refuse a bundle the running version does not satisfy, and without the field the `@deepseek-ai/dsh*` peer ranges decide. A `workspace:` value in `engines.dsh` is invalid. `docs/user/develop/basic/publish.md`; `packages/boot/app-boot/README.md#profiles`
- **H5 (MUST)** DSH packages whose instances must be shared with the host go in both `peerDependencies` and `devDependencies`; independently versioned third-party dependencies and stateless utilities go in `dependencies`. `docs/user/develop/basic/publish.md#install-into-a-profile`
- **H6 (MUST)** The icon is an in-package SVG, PNG, JPEG, or WebP up to 256 KiB, self-contained (no scripts, event handlers, animation, external images, fonts, or `foreignObject`), declared through top-level `package.json` `icon` or the `./icon` export; absolute paths, URLs, and symlinks leaving the package are rejected. `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#display-metadata-and-icon`; `docs/cookbook/adding-a-package.md#5-add-optional-plugin-display-metadata`
- **H7 (MUST)** Keep the published payload closed and minimal: every relative runtime import and emitted asset is covered by `files`, and no source-only or build-only artifact ships. `packages/client/AGENTS.md#dependency-declaration`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#display-metadata-and-icon`
- **H8 (MUST)** Ship plain ESM on the Host side (no CJS-only exports reachable from the entry) and use the lazy-CJS factory protocol for the browser artifact; do not introduce a second module format because it happened to work in one launch mode. `AGENTS.md#conventions`; `packages/client/modules/README.md#lazy-cjs-model`
- **H9 (SHOULD)** Re-audit these standards when the `engines.dsh` pin moves: the harness is a developer preview whose public APIs are pre-stable, so a rule derived from an older checkout may no longer hold. `AGENTS.md` (pre-stable APIs); `docs/upgrade-guide/`

## I. Tests expected from a plugin repository

- **I1 (MUST)** A `node --test` suite (or the repo's configured test runner) covers, at minimum: package manifest and patch YAML shape, locale JSON shape and key parity, Host entry export form, and each pure helper. `packages/AGENTS.md`; `../SKILL.md#plugin-repository-anatomy`
- **I2 (MUST)** A registration-disposal test exercises the real entry (`apply` against a stub context, then dispose the fiber) and asserts the listener, tool, timer, or slot entry is gone; asserting that dispose was called is not evidence. `packages/AGENTS.md` (registry contributions prove disposal); `.agents/skills/cordis-styling-nitpicking/SKILL.md#reporting`
- **I3 (MUST)** Test the shipped entry path, not a hand-mounted reimplementation: import the published `index.js`/`client.js` or install through the Loader, because a hand-mounted `ctx.plugin(...)` never catches an invalid Loader export. `.agents/skills/dsh-code-review/SKILL.md` (real entry path); `docs/testing.md#test-the-real-entry-path`
- **I4 (SHOULD)** Add one negative control per acceptance rule: invalid config fails the load, a malformed manifest is rejected, and missing locale fields fall back rather than crash. `.agents/skills/dsh-code-review/SKILL.md#manual-checks`
- **I5 (SHOULD)** CI runs lint plus the test suite on a pinned Node version, and where a DSH install is available, a smoke install with `dsh --profile <name> --dump-config` to prove the layer composes without booting. `docs/user/develop/basic/publish.md#install-into-a-profile`
- **I6 (SHOULD)** Pin stable model-visible strings verbatim and assert the failure path's visible outcome, since the out-of-tree repo has no recorded-session snapshot harness. `packages/AGENTS.md` (pin stable model-visible text); `docs/testing.md#when-a-snapshot-test-is-required`

## J. Security and trust

- **J1 (MUST)** Treat installation as executing plugin code in the Host process, outside any agent sandbox: read the source before installing, ask the user, and never install a package whose code you have not reviewed. `docs/user/develop/basic/publish.md#installing-from-github-the-build-script-catch`; `packages/boot/app-boot/README.md#profiles` (checks are not a sandbox)
- **J2 (MUST)** Build scripts (`prepare`, `postinstall`) run only after an explicit per-package allowlist; prefer prebuilt npm or a packed tarball, and pin a git commit so a later push cannot change what runs. `docs/user/develop/basic/publish.md#installing-from-github-the-build-script-catch`
- **J3 (MUST)** Never hand-edit a profile's `package.json` or `cordis.patch.yml`, never create packages under `$DSH_HOME`, and never run pnpm inside a profile directory; `dsh plugin --profile <name> add <path>` or the Plugins page owns those writes. `packages/preset/agent-preset/skills/cordis-plugin-development/SKILL.md`
- **J4 (MUST)** An incompatible bundle is blocked at install and startup; a version exemption is an explicit, exact plugin-and-version grant with a risk warning, never a blanket range. `packages/boot/plugin-manager/README.md#version-compatibility-and-exemptions`; `apps/cli/README.md`
- **J5 (SHOULD)** Report the install outcome from the returned `application` and `warnings`, distinguishing `failed`, `overridden`, and `restart-required`, and let the user decide when to restart a running profile. `packages/preset/agent-preset/skills/cordis-plugin-development/references/host-plugin.md#install-enable-and-observe`; `packages/preset/agent-preset/skills/cordis-plugin-development/SKILL.md`

## Not applicable out-of-tree

In-tree machinery that must not be cargo-culted into a plain-JS bundle, and what to do instead:

| In-tree machinery | Out-of-tree equivalent or limitation |
|---|---|
| `SessionEventMap` extension, new session event types, session-format versions | Not available and actively refused: live `append()` cannot mark events ignorable, so a Session with a plugin-invented type refuses to reopen. Derive from existing events or use a storage service. `docs/cookbook/adding-a-session-format-version.md`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#stability` |
| Session projections (`ctx.sessionProjections.register`, typed `wire` views) | Partly available: the runtime registry is a public service an installed plugin may register a unit on, and it is the recommended way to avoid rescanning. In-tree-only are the typed `SessionEventMap` binding and shipping format-version migrations; the `stateVersion`/checkpoint contract still binds your state to DSH releases. `packages/session/session-projection/README.md`; `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#performance` |
| Typert `@Remote` methods and generated Host/Client pairs | Cannot be added: they require generated remote contributions and a matching package build. Use existing services and events; a bundle may configure shipped implementations but cannot add one. `docs/cookbook/adding-a-remote-api.md`; `references/surfaces.md#not-covered-here` |
| In-tree Client packages and their stores, hooks, and primitives | Must not be imported or bundled; the tokens and the copied behavior are the only shared styling dependency. `packages/preset/agent-preset/skills/cordis-plugin-development/references/practices.md#ui` |
| Per-file 100% coverage gate, snapshot fixtures, doc budgets, workspace constraints, `verify-*` gates | Not run against an out-of-tree repo; the equivalent is I1–I6 plus the plugin README, and the review duties those gates would enforce stay yours. `AGENTS.md#commands`; `docs/testing.md` |
| `dsh.profile` manifests, in-box bundle ordering, Agent Presets | You author one bundle; users own their profile and its layer order. A preset placement is configured through the profile, not shipped as a bundle row. `docs/user/develop/basic/publish.md#two-concepts-two-manifests` |
| New seam implementations (shell, sandbox, session persistence, subagent, terminal providers) | In-tree seam packages only; a bundle configures the shipped provider instead. `references/surfaces.md#not-covered-here` |

## Before calling the plugin done

Run the rules that a reviewer would run: A1–A8 disposal, C1–C5 config, D2/D5/D7 model-visible facts, E5–E7 locale, F1–F7 tool contract, G1–G7 UI, H1–H8 packaging, I1–I3 tests, J1–J5 trust. Record in the README what was verified live, in which theme and locale, and what remains unverified.
